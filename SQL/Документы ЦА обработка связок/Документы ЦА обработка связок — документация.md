# Документы ЦА — обработка связок

Отчёт о том, как сотрудники обрабатывают связки документов: от поступления связки до верификации. Одна строка отчёта — одна связка (последняя версия по событиям).

Отчёт показывает:
- этапы обработки: подготовка → сканирование → синхронизация → распознавание → верификация;
- время на каждом этапе;
- количество документов (распознано и нет);
- рекламации (выявленные системой, удалённые, добавленные, подтверждённые);
- флаг «закончено в тот же день»;
- календарь рабочих дней.

## 1. Шапка

| Поле | Описание |
|------|----------|
| **Коннект** | Starrocks (`staroks (BKS)`) |
| **Сложность** | Средняя |
| **Источники** | S0266 (события обработки связок, поступают через Kafka), D_EMPLOYEE (справочник сотрудников DWH) |
| **Ссылка** | — |

## 2. Источники данных

| № | Таблица / Представление | Схема | Назначение |
|----|------------------------|-------|------------|
| 1 | `S0266_EVENT_BUNDLE` | `BI_VIEW` | События по связкам: даты этапов, статусы, количество документов, рекламации, логин сотрудника |
| 2 | `D_EMPLOYEE` | `SS_NEW` | ФИО и ID сотрудника по логину (активные записи системы-источника 8) |

## 3. Схема связей

```
EVENT (B)  ← S0266_EVENT_BUNDLE с коррекцией времени (+5 часов, см. раздел 6)
    └─ JOIN SS_NEW.D_EMPLOYEE (DE)  ON UPPER(DE.EMPLOYEE_LOGIN) = UPPER(B.LOGIN)
                                    AND S_ROW_STATUS = 'A' AND S_SOURCE_SYSTEM = 8
       → FLG (последняя версия связки: BUNDLE_LS = 1)
            └─ JOIN ACT  ON ACT.BUNDLE_NUMBER = FLG.BUNDLE_NUMBER
                         (ACT = события S0266_EVENT_BUNDLE с ACTION = 'scanfinish')
       → [ANL] (Qlik)

[ANL]  ← День →  MasterCalendar (только рабочие дни Пн–Пт)
```

## 4. Структура данных

**Часть 1: [ANL] — связки с этапами обработки**
- **Источник:** `BI_VIEW.S0266_EVENT_BUNDLE` (события) + `SS_NEW.D_EMPLOYEE` (сотрудник).
- **Гранулярность:** связка (`Номер связки`), одна строка.
- **Как строится:**
  1. `EVENT` — события со сдвигом времени на +5 часов для записей, созданных начиная с 03.07.2026 12:04:08.
  2. `FLG` — события присоединяются к сотруднику по логину. Из всех версий связки остаётся последняя: `DENSE_RANK() OVER (PARTITION BY bundle_number ORDER BY s$change_date DESC) = 1`.
  3. `ACT` — события с `ACTION = 'scanfinish'`. Они дают количество листов, которые не удалось распознать.
  4. `FLG` и `ACT` соединяются по номеру связки; связки без события `scanfinish` в отчёт не попадают.
- **Фильтры:** других фильтров по датам или статусам нет.

**Часть 2: MasterCalendar — календарь**
- Диапазон дат: от минимального до максимального `День` в `[ANL]`.
- Выбраны только рабочие дни (Пн–Пт).
- Поля: день, день месяца, день недели, номер и год недели, неделя в формате `ГГГГ-Wнн`, год, флаг YTD.

## 6. Бизнес-логика

### Стадии обработки связки

| Этап | Начало | Конец | Время (поле) |
|------|--------|-------|--------------|
| Подготовка | Поступление (`CREATED_DATE`) | Начало сканирования | `Время подготовки` |
| Сканирование | Начало сканирования | Конец сканирования | `Время сканирования` |
| Синхронизация | Конец сканирования | Начало распознавания | `Время синхранизации` |
| Распознавание | Начало распознавания | Конец распознавания | `Время распознования` |
| Верификация | Конец распознавания | `WORK_END_DATE` | `Время верификации` |
| Общее | `WORK_START_DATE` | `WORK_END_DATE` | `Затраченное время` |

Время считается в источнике через `timediff` и выводится как `чч:мм:сс`.

### Коррекция времени
Для событий с `created_date >= 2026-07-03 12:04:08` к полям `created_date`, `scan_start_date`, `recognition_start_date`, `recognition_end_date`, `recognition_end_date_final`, `work_start_date`, `work_end_date` прибавляется 5 часов. Поле `scan_end_date` не корректируется (см. примечания). Признак применения определяется по исходной `created_date`.

### Конец распознавания
Если `RECOGNITION_END_DATE` пуста, берётся `RECOGNITION_END_DATE_FINAL`. Это значение используется и как начало верификации.

### Версия связки
В отчёт попадает только последняя версия связки (по `s$change_date`). Более ранние версии отбрасываются.

### Календарь
- Только рабочие дни: `WeekDay < 5` (Пн–Пт).
- `Неделя` = `Год недели-Wномер`, например `2026-W41`.
- `YTD_Флаг` — признак «с начала года по сегодня».

## 7. Примечания

**Требует проверки**
- **Незакрытые комментарии в тексте SQL.** Закомментированный старый запрос (строки 58–140) содержит внутри `*/` (строки 62 и 65). Блочные комментарии SQL не вкладываются, поэтому комментарий закрывается раньше, чем кажется, и остаток старого запроса остаётся «живым». Я скрипт не запускал и не знаю, как это обрабатывает Qlik. Если отчёт сейчас грузится нормально, всё в порядке; если нет — удалить старый блок целиком.
- **Сдвиг +5 часов не применён к `scan_end_date`.** Остальные даты сдвигаются, а конец сканирования — нет. Для связок после 03.07.2026 `Время сканирования` может оказаться занижено на 5 часов (вплоть до отрицательного значения), а `Время синхранизации` — завышено на столько же. Нужно сверить с владельцем источника.
- **Дубли строк при JOIN с `ACT`.** Событий `scanfinish` по одной связке может быть несколько (разные `S$KAFKA_TIMESTAMP`), и тогда строка связки размножается. Связки без `scanfinish` в отчёт не попадают вообще.
- **Дубли при поиске сотрудника.** Если по одному логину есть несколько активных записей в `D_EMPLOYEE`, строки связки тоже задваиваются.

**Особенности полей**
- **`Время подготовки`** считается от поступления связки (`CREATED_DATE`), а не от `Начало подготовки` (= `WORK_START_DATE`). Поэтому оно не равно разности полей «Начало подготовки» и «Конец подготовки», которые показаны рядом.
- **`Кол-во листов`** на самом деле содержит число нераспознанных листов (`PAGES_NOT_RECOGNIZED`). Поле `PAGES_IN_BUNDLE` выбирается в SQL, но в Qlik не загружается.
- **Длительности загружаются как текст.** Поля `Время …` приходят из SQL как строки `чч:мм:сс`, а в Qlik оборачиваются в `Time()`. Если длительность больше 24 часов, Qlik может не распознать значение, и поле станет пустым.
- **Опечатки в названиях полей:** `Время синхранизации` (синхронизации), `Время распознования` (распознавания). Если поля используются в приложении, переименование потребует правок в визуализациях.
- **Не загружаются:** `CHANGE_DATE`, `EMPLOYEE_LOGIN`, `EMPL_ID`, `ACTION` — они есть в SQL, но не попадают в `[ANL]`.

**Календарь**
- Выходные в календаре исключены. Связки, поступившие в субботу или воскресенье, не получат год, неделю и другие атрибуты календаря.
- Поле `День` в `[ANL]` отображается как `ДД.ММ.ГГГГ`, в календаре — как `ГГГГ-ММ-ДД`. Связь работает по числовому значению даты.

**Прочее**
- Дата коррекции времени (`2026-07-03 12:04:08`) зашита константой в 7 местах запроса. Если исправление источника будет отменено или сдвинуто, менять придётся везде.
- **Обновление:** полная перезагрузка при каждом reload, без инкрементальной загрузки.
