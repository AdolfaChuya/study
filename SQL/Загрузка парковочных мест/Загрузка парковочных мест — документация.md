# Загрузка парковочных мест

Отчёт показывает загрузку парковочных мест сотрудников по месяцам:
- кто и на какой парковке закреплён, с оргструктурой, автомобилем и сроками выдачи места;
- сколько дней место использовалось;
- отсутствия сотрудника (отпуск, больничный) по данным HR;
- «Флаг обоснованности»: набралось ли за месяц 10 дней использования и отсутствий;
- отдельно — очередь заявок на парковку.

Данные с 01.2025. Парковка «САТТИ» исключена.

## 2. Источники данных

| № | Таблица / Представление | Схема / Путь | Назначение |
|----|------------------------|--------------|------------|
| 1 | `DATA_PARKING` | `S0008` | Помесячные закрепления парковочных мест: сотрудник, оргструктура, авто, дни использования, тип места |

## 3. Схема связей

```
DATA_PARKING (t1: последняя версия по сотрудник × период × место)
    UNION ALL DATA_PARKING (текущие типы мест, PERIOD IS NULL → MAX(PERIOD))
      → pivot_parking_timeline (Qlik)
          ├─ LEFT JOIN Σ[Дней на дату]         ON UniqueSpotID + Период  → Temp_Sum_Day
          ├─ LEFT JOIN EMPLOYEES+USERS_POSITIONS ON [Имя сотрудника]      → POSITION, ID
          │    └─ LEFT JOIN Position ID CATEGORY ON ID                   → category
          └─ → Final_Table
                └─ LEFT JOIN Σ дней отсутствия ON KEY_TRIP (месяц + ФИО) → Temp_Sum_Dayoff
                     → Final_Table_2

STATUS.qvd → KASPI_* (группировка непрерывных отсутствий) → FINAL_ABSENCE_REPORT_2

Итоговая модель:
Final_Table_2 ──KEY_TRIP── FINAL_ABSENCE_REPORT_2
ZAYAVKI_PARKING               (не связана с остальными таблицами)
```

## 4. Структура данных

**Часть 1: Закрепления мест (`Final_Table_2`)**

Строки собираются из двух запросов к `S0008.DATA_PARKING`, объединённых через UNION ALL.

- **Подчасть A — история по месяцам:**
  - Фильтры: `PERIOD >= 2025-01-01`; парковка не «САТТИ»; номер места и ФИО заполнены.
  - До 02.2026 берутся только строки с `DAY > 0`. С 02.2026 строки с нулём дней тоже попадают в отчёт.
  - Дедупликация: для каждой тройки сотрудник × период × место берётся последняя версия по `ENDDATE`.
- **Подчасть B — текущее назначение мест:**
  - Строки с пустым `PERIOD`, последней `ENDDATE` и заполненным `TYPOFPARKINGSPACE`.
  - Им проставляется `PERIOD = MAX(PERIOD)`.
- **`Actual_Parking_Assignment`:**
  - Для будущих периодов берётся тип места как есть.
  - Для прошлых и текущего — тип места из последнего периода по этому месту (номер места + парковка).
- **Исключения в Qlik:**
  - пустой `UniqueSpotID`;
  - место «10» на парковке «Наземный Каблан» без сотрудника;
  - повторно парковка «САТТИ».

**Часть 2: Отсутствия (`FINAL_ABSENCE_REPORT_2`)**
- **Источник:** `STATUS.qvd` с 2025 года. Статусы «стандартное отсутствие» и «длительное отсутствие». Берутся только сотрудники, которые есть в парковочных данных (`EXISTS` по ФИО).
- **Логика:**
  1. Записи очищаются от дублей и сортируются по ФИО и дате.
  2. Идущие подряд дни с одним и тем же статусом объединяются в группу (Peek/GroupID).
  3. Группы режутся по месяцам.
  4. Для каждой группы считаются дата начала, дата окончания и число дней.
- **Связь** с закреплениями: по `KEY_TRIP` = «месяц год» + ФИО без пробелов в верхнем регистре.

**Часть 3: Очередь заявок (`ZAYAVKI_PARKING`)**
- **Источник:** `S0008.PARKING_REQUESTS_IN_THE_QUEUE`, загружается целиком без фильтров.
- С остальной моделью не связана, используется как отдельная таблица.

## 6. Бизнес-логика

### Флаг обоснованности

| Условие | Результат |
|---------|-----------|
| `Temp_Sum_Day + Temp_Sum_Dayoff >= 10` | `>= 10` (место используется обоснованно) |
| Иначе | `меньше 10` |

- `Temp_Sum_Day` — сумма `Дней на дату` по месту (`UniqueSpotID`) за период. Суммируются дни всех сотрудников, закреплённых за этим местом.
- `Temp_Sum_Dayoff` — сумма дней отсутствия сотрудника за месяц. Если отсутствий нет, берётся 0.

### Прочие правила
- До 02.2026 строки с 0 дней использования исключаются, с 02.2026 — включаются.
- Парковка «САТТИ» исключается везде.
- Жёстко заданное исключение: место «10» на парковке «Наземный Каблан» без сотрудника.
- Отсутствия, которые переходят через границу месяца, делятся на отдельные строки по месяцам.

## 7. Примечания

**Правила расчёта**
- **Смешение уровней во флаге:** дни использования суммируются по месту (по всем сотрудникам на нём), а дни отсутствия — по конкретному сотруднику. Если на одном месте несколько человек, флаг может завышаться.

**Связи и ключи**
- **Сопоставление по ФИО:**
  - Должность и отсутствия подтягиваются по ФИО, а не по ИИН или табельному номеру.
  - У полных тёзок данные могут перепутаться.
  - Если ФИО в DATA_PARKING и в HR записано по-разному, связи не будет.
- **Заявки не связаны с моделью:** у `ZAYAVKI_PARKING` нет общего ключа с остальными таблицами, фильтры по сотруднику на неё не действуют.

**Хрупкие места в SQL**
- **UNION ALL:** в первой части используется `SELECT *`, во второй колонки перечислены явно. Если в `DATA_PARKING` добавят или переставят колонку, объединение сломается или данные сместятся по колонкам.
- **FIRST_VALUE** не пропускает NULL. Если в последнем периоде тип места пустой, «Назначение парк места» тоже будет пустым.

**Мелочи**
- `EMPLOYMENTTYPE` загружается под названием «Тип парковки». Стоит проверить, что поле действительно означает тип парковки, а не тип занятости.
- В начале скрипта остался закомментированный старый запрос `Data_Parking`.

**Обновление:** полная перезагрузка при каждом reload. Флаг «Текущий месяц» пересчитывается относительно даты перезагрузки.
