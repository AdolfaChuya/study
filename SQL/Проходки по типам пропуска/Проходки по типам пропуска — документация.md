# Проходки по типам пропуска

Анализ того, чем сотрудники проходят через точки доступа (СКУД): физической картой, KMP, U-PROX или по Face ID. Отчёт строится по онлайн-логам проходов, считает дни с проходами каждого типа и относит сотрудника к сегменту («Преимущественно KMP», «KMP + CARD», «Смешанный профиль» и т.д.). Также показывает, как менялся сегмент сотрудника от месяца к месяцу и от квартала к кварталу.

Месячная аналитика (дни и сегменты) считается только по проходам через два здания: Конкорд и Каблан. Логи берутся с 01.01.2024.

## 1. Шапка

| Поле | Описание |
|------|----------|
| **Коннект** | Starrocks (`staroks (BKS)`) + Excel (`AttachedFiles`) |
| **Сложность** | Высокая |
| **Источники** | СКУД (схема S0099), Excel-справочники |
| **Ссылка** | — |

## 2. Источники данных

| № | Таблица / Представление | Схема / Путь | Назначение |
|----|------------------------|--------------|------------|
| 1 | `LOGS_ONLINE` | `S0099` | Онлайн-логи проходов (JSON): сотрудник, точка доступа, время, направление, ключ |
| 2 | `PERSONAL` | `S0099` | Справочник сотрудников СКУД: ID и ФИО |
| 3 | `DEVICES` | `S0099` | Справочник устройств (точек доступа): ID, название, конфигурация |
| 4 | `DEVICES_Города_Здания.xlsx` | `lib://AttachedFiles` (лист `Sheet1`) | Здание и город для каждой точки доступа |
| 5 | `FIO_CAT.xlsx` | `lib://AttachedFiles` (лист `UPR`) | Список сотрудников, у которых есть пропуск U-PROX |
| 6 | `CAT_2.xlsx` | `lib://AttachedFiles` (лист `Лист4`) | Список сотрудников, у которых есть пропуск KMP |

## 3. Схема связей

```
LOGS_ONLINE (JSON) → TMP_LOGS (проходы с дедупликацией, тип пропуска)
    ├─ фильтр сотрудников: Exists(EmpID_Valid) ← PERSONAL
    └─ определение типа пропуска: Exists(Kaspi_ID) ← KMP_List, Exists(Uprox_ID) ← Uprox_List
    → LOGS_PRE (сотрудник × точка доступа × тип × день)

LOGS_PRE ── Map_DevicePlace (ACCESSPOINT → здание, DEVICES + Excel) → только Конкорд и Каблан
    ├─ Temp_Category_Counts → User_Activity_Pivot → User_Segmentation → Migration_Map (месяц)
    └─ User_Quarter_Pivot → User_Quarter_Segmentation → Quarter_Migration_Map (квартал)

Итоговая модель Qlik:
PERSONAL (EmpID_Valid) ── LOGS_PRE ── (ACCESSPOINT) ── DEVICES
User_Segmentation   (PivEmpID_Valid, PivMonthYear)   — без связей
Migration_Map       (MigEmpID_Valid, CurrentMonth)    — без связей
Quarter_Migration_Map (MigQ_EmpID_Valid, CurrentQuarter) — без связей
Uprox_List, KMP_List — без связей (используются только через Exists)
```

## 4. Структура данных

**Часть 1: Справочники**
- `PERSONAL` — действующие сотрудники: тип `EMP`, должность заполнена, в ФИО нет цифр, знака «№» и слов «Старший Смены».
- `DEVICES` + Excel — точки доступа с названием, зданием (`DEVICE_PLACE`) и городом (`DEVICE_TOWN`). `Map_DevicePlace` связывает `ACCESSPOINT` со зданием.
- `Uprox_List`, `KMP_List` — списки сотрудников с пропусками U-PROX и KMP.

**Часть 2: TMP_LOGS → LOGS_PRE — проходы с типом пропуска**
- **Источник:** `S0099.LOGS_ONLINE`, JSON-массив `logs`. Если массива нет, используется одиночное событие `LOGS`.
- **Фильтры:** время не раньше 01.01.2024, направление не равно 3, сотрудник задан, сотрудник входит в `PERSONAL`.
- **Дедупликация:** проходы одного сотрудника через одну точку доступа с интервалом 5 секунд и меньше считаются одним (раздел 7).
- **Тип пропуска:** вычисляется по правилам раздела 6.
- **Результат `LOGS_PRE`:** количество проходов (`PassCount`) по сотруднику, точке доступа, типу пропуска и дню. Добавлены ключ `%Key_DayActivity` и месяц (`MonthYear`).

**Часть 3: User_Segmentation — сегменты по месяцам**
- **Данные:** `LOGS_PRE`, только точки доступа в зданиях Конкорд и Каблан.
- **Метрика:** количество дней с проходом каждого типа (`CARD`, `KMP`, `U-PROX`, `FACE-ID`) за месяц и доля каждого типа от суммы.
- **Результат:** сегмент сотрудника в месяце (`User_Segment`), признаки наличия в списках KMP и U-PROX.

**Часть 4: Migration_Map — переходы между месяцами**
- Для каждого сотрудника и месяца подтягивается сегмент предыдущего месяца. Если в предыдущем месяце проходов не было, он пустой.

**Часть 5: Quarter_Migration_Map — сегменты и переходы по кварталам**
- Считается так же, как по месяцам, но по кварталам и без фильтра по зданиям (см. раздел 7). Результат — сегмент текущего и предыдущего квартала с названиями вида `Q1 2026`.

## 6. Бизнес-логика

### Тип пропуска (`PASS_CATEGORY`)
Правила применяются по порядку, срабатывает первое:

| Условие | Тип |
|---------|-----|
| Ключ (`keyHex`) пуст, равен `-1` или `000000`, либо точка доступа 406 или 504 | FACEID |
| Код объекта (`FACILITY_CODE`) = 100, проход не раньше 01.01.2025 и сотрудник есть в списке KMP | KMP |
| `FACILITY_CODE` из 117, 138, 37, 25, 179 и сотрудник есть в списке U-PROX | U-PROX |
| Остальное | CARD |

Код объекта и номер карты берутся из последних 6 шестнадцатеричных знаков ключа: `код объекта = число DIV 65536`, `номер карты = число % 65536`. Для пустого ключа и `000000` значение равно −1.

### Сегмент сотрудника
Доли считаются от `TotalDays`. Правила применяются по порядку:

| Условие | Сегмент |
|---------|---------|
| Доля KMP ≥ 75% | Преимущественно KMP |
| Доля FACE-ID ≥ 75% | Преимущественно FACE-ID |
| Доля CARD ≥ 75% | Преимущественно CARD |
| Доля U-PROX ≥ 75% | Преимущественно U-PROX |
| Сумма долей двух типов ≥ 75% и доля каждого > 10% | Гибрид, в порядке проверки: KMP + FACE-ID, KMP + CARD, KMP + U-PROX, FACE-ID + CARD, FACE-ID + U-PROX, CARD + U-PROX |
| Иначе | Смешанный профиль |

### Месячная метрика
- `DayHits` = число различных дней с проходом данного типа за месяц.
- Учитываются только проходы через точки доступа в зданиях «Конкорд» и «Каблан» (по `DEVICE_PLACE`).

### Миграция
Для сотрудника сегмент текущего месяца (или квартала) сопоставляется с сегментом предыдущего. Месяц считается в формате `MMMM YYYY`, квартал — как начало квартала.

## 7. Примечания

**Расхождения между месячной и квартальной логикой**
- **Квартальный расчёт считает иначе, чем месячный.** Месячный — дни с проходом, только в зданиях Конкорд и Каблан. Квартальный берёт все точки доступа и складывает строки `LOGS_PRE`, то есть число комбинаций «точка доступа × день», а не дней. Знаменатель `TotalDays` при этом — число различных дней. Если сотрудник в один день прошёл через две точки, доли могут превысить 100%, и сегмент квартала получится некорректным. Нужно привести расчёты к одному правилу.
- **В месячном `TotalDays` сумма дней по типам, а не число различных дней.** День, в который сотрудник проходил разными типами пропуска, учитывается несколько раз. Доли при этом в сумме равны 100%.

**Логика обработки логов**
- **Дедупликация по 5 секундам считается по цепочке.** Для каждого прохода сравнивается время с предыдущим проходом (даже если тот был отброшен). Если проходы идут подряд с интервалом ≤ 5 секунд, остаётся только первый из всей серии.
- **Сдвиг времени −5 часов** (`raw_time − 18000`) зашит в запрос. Зачем он нужен, в скрипте не сказано; результат зависит от часового пояса сервера. От него зависят дата, месяц и квартал проходов около полуночи.
- **Неясные значения кодов:** `direction != 3`, точки доступа 406 и 504 (отнесены к Face ID), коды объектов 100, 117, 138, 37, 25, 179. В скрипте они не расшифрованы.
- **`Exists(ACCESSPOINT)` в `Temp_Category_Counts` ничего не фильтрует.** Все значения поля уже загружены. Реально отбор делает только `Match` по зданию. Пояснение, на которое ссылается комментарий («см. пояснение ниже»), в скрипте отсутствует.
- **Точки доступа, которых нет в Excel `DEVICES_Города_Здания.xlsx`,** `ApplyMap` оставляет как есть (в виде кода), и они не проходят отбор по зданию. Новые точки нужно добавлять в файл.
- **Принадлежность к KMP и U-PROX определяется по спискам Excel.** Если сотрудника нет в списке, проходы с кодом объекта 100 считаются CARD. Списки нужно обновлять вручную.
- **Выходные и праздничные дни не исключаются.**

**Связи в модели**
- **Таблицы сегментов и миграций не связаны с `PERSONAL`.** У них свои имена полей (`PivEmpID_Valid`, `MigEmpID_Valid`, `MigQ_EmpID_Valid`), поэтому ФИО сотрудника рядом с сегментом не показать без доработки.
- **`Uprox_List` и `KMP_List` с моделью не связаны,** используются только в `Exists`.
- **Столбец `PassCount` и ключ `%Key_DayActivity` загружены, но дальше в расчётах не используются.**

**Хрупкие места**
- Пороги 75% и 10%, коды объектов, номера точек доступа, дата начала KMP (01.01.2025) и дата начала логов (`1704067200` = 01.01.2024) зашиты в код.
- Названия зданий «Конкорд» и «Каблан» зашиты в `Match`.
- `PERSONAL` исключает сотрудников без должности, с цифрами и «№» в ФИО и «Старший Смены». Фильтр по тексту ФИО может отсечь лишнее.

**Персональные данные:** в Excel-списках (`FIO_CAT.xlsx`, `CAT_2.xlsx`) и `PERSONAL` содержатся ФИО сотрудников и номера карт. Доступ к приложению стоит ограничить.

**Обновление:** полная перезагрузка при каждом reload. Весь поток `LOGS_ONLINE` с 2024 года читается заново, это самый тяжёлый шаг скрипта.
